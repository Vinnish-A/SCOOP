# SCOOP First Principles

SCOOP serves biological questions and reusable analysis; framework completeness, default tools, or technical success do not substitute for completing research. This page provides the common principles for analytical decisions; see [module descriptions](modules-and-outputs.md) for module defaults and interfaces, and [runtime](../runtime.md) for release maintenance.

## Judgment and measurement

- **Biology adjudicates; computation provides evidence.** Keep identity, state, malignancy, and confidence separate; assess them jointly using tissue-matched atlases, original literature, positive/exclusion markers, co-detection in the same cells, and patient context. Automatic labels must not determine names, and stress/IFN/proliferation are not new types by default. CNV is supporting evidence; low/neutral CNV does not establish normality. Use an allowlist of reviewed identities for normal references, excluding mixed, low-quality, and unresolved populations; do not indiscriminately include all “non-epithelial” cells.
- **Confirm the clinical unit before interpreting trends.** Connect cell→sample/timepoint→patient→endpoint, and first check pairing and the number of available patients; retain tissue/PBMC, pCR/cCR/TRG, and treatment regimens separately. Cells/bins/ROIs do not increase the number of independent patients. Proportions, UCell, source pseudobulk, and scSurvival risk answer different questions; preserve denominators, scope, effect units, and endpoint direction, and do not swap definitions in pursuit of significance.
- **Assess technical correctness and biological support separately.** Convergence, non-negativity, and CPU/GPU agreement do not establish that deconvolution identities are correct; marker and atlas matches do not establish function; CCC does not establish mechanism; multiple seeds with the same initialization do not constitute independent robustness; fitted risk is not predictive validation. First check reference identifiability, patient coverage, sampling, and composition, then decide what can be claimed.

## Metadata and batch contract

Before QC, integration, and cross-source comparisons, organize verifiable metadata tables and mappings: retain exact cell/source/native IDs and connect the original dataset, sample, patient, library/capture, assay/platform, tissue, condition/treatment, and timepoint. Record provenance, aliases, and conflicts for each field, and explicitly mark unknowns as unknown; a sample must not stand in for a patient, and identical barcodes do not establish that cells are the same. Unknown nonessential fields do not block unrelated work; they limit only methods or conclusions that depend on those fields.

Use a stable `original_dataset_id` as the primary source key for integration batches: define it from the original study dataset accession/release identifier or an explicit subset of the original release, and retain aliases and container mappings; map processed data views, files, and processing versions of the same dataset separately, without automatically splitting them into new batches. Trace collection containers such as GRIT back to their constituent original datasets; do not automatically treat a collection as a single batch. Study, file, patient, sample, and technical library/capture are different levels. Declare technical sub-batches such as assay/capture within an original dataset only when evidence supports them; do not arbitrarily remove patient, condition, or target identity as technical effects. When source and biological condition are completely confounded, document what is unidentifiable rather than treating forced mixing as a solution.

For each method, separately register its input expression/latent layer, actual batch keys and covariates, real interface and parameters, whether it was executed, input/output axes and hashes, applicability, and verification:

| Purpose | Meaning of batch handling |
| --- | --- |
| Integration, neighborhoods, and clustering | Latent correction with Harmony/scVI and similar methods applies to their explicitly defined outputs; retain uncorrected representations and marker/source checks, and do not assume that the original expression has been corrected. |
| Cross-dataset NMF | Before fitting, actually execute and verify an expression-level batch interface supported by the engine/preprocessing, or explicit within-model batch handling; check scale, non-negativity, gene axes, and actual outputs. CP10k, std scaling, balanced anchors, or a file named `corrected_h5ad` do not establish that this step has occurred. |
| Cluster/subcluster/final-label marker DEG | Once clustering, its inputs, and measurement scope have been verified, directly perform conventional gene-level differential tests on the actual expression layer; batch stratification is not a mandatory prerequisite. Check source/batch and measurement differences as needed; report contrasts, denominators, effects, measured genes, and testing scope. Cell-level evidence does not represent patient replication. |
| Patient/condition DEG | Model the design using independent biological replicates, pairing, conditions, and technical batches; explicitly state limitations when confounding prevents identification. |

See the [annotation workflow](../markers/annotation-workflow.md) for the review order for broad biological classes and fine subgroups, and for the main process's responsibilities. Reliable clustering, conventional DEG, and tissue markers can establish broad classes without NMF as a prerequisite; formal fine-subgroup analysis and adjudication must meet all prerequisites and evidence requirements in that workflow.

Original counts are read-only, and corrected expression is a separate derived view with a methodological basis; do not temporarily clip signed latent values or arbitrary regression residuals at zero and present them as usable expression, or reconstruct counts from normalized values. Non-negativity transformations defined by the method itself (such as clipping in an official correction workflow) may be used, but accurately record their definition, execution, and effects, and retain original counts. Evaluate all sources using the same measurement comparability rules; collection membership does not permanently lower an evidence grade. Do not fill unmeasured/unknown structural masks with zeros. For spatial and multimodal data, separately declare the applicability of batch handling to reference, platform, section/FOV, assay, and pairing units; do not blindly apply the same Harmony procedure to different measurements or overwrite original counts.

## Practical execution

- **Bypass unusable interfaces and document it.** When a CLI lacks parameters/backends, hangs, or does not fit the scale, use the actual API, a project adapter, or isolated dependencies directly, preferentially reusing the managed environment. Do not halt research to repair the framework or experimentally reinstall a shared release. In existing logs/receipts, record the reason, actual algorithm and environment, inputs/parameters, outputs, and verification; distinguish scheduling changes, parameter changes, and algorithm replacements, and do not present them as native stage completion. Biological review, patient units, and source-data constraints still apply.
- **Run a representative small task before expensive computation.** Doctor only discovers dependencies; actually validate the required backend, input semantics, and resources. Check batch/epochs/warmup, sparse reads, and N² steps; independent libraries/lineages may run in parallel, with total threads and memory controlled and progress and checkpoints saved per unit. Choose parameters from the actual scale rather than copying constants from old projects; do not report acceleration that has not actually been completed as a full-data benefit.
- **Redo only affected work and deliver objects that remain usable.** Original counts are read-only; recover from save failures using valid results. Do not treat missing values or not_assessed as zero. Retain stable state and complete graph descriptions in H5AD, and externalize large tables; verify IDs/order, field types, and save/read round trips, and avoid matrix aliasing mutations. Report actual conclusions, limitations, and a single current entry point, preserving source tables, decisions, and reproduction paths; a “successful run” without biological content is not a deliverable.

Default methods are interpretable starting points, not exclusive restrictions. Review targets affected judgments: a review can be completed with explicitly retained unresolved identities, while independent branches continue; bypassing a tool does not substitute for approval of supervision labels. Project experience should update the judgments above or the relevant module, rather than turning every failure into a new prohibition.
